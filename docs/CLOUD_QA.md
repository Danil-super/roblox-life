# Приёмка облачных сохранений

Локальный P0-цикл уже проверен, но SAVE-01 пока открыт. Ни memory roundtrip,
ни восстановление модели после respawn не считаются облачным повторным входом.

## Подготовленная сборка

Обычный `default.project.json` оставляет Studio в MemoryPreview. Исходник Storage
больше не нужно переключать перед тестом. После подготовки отдельной тестовой
experience можно собрать QA-копию:

```bash
python3 scripts/build_cloud_test.py --universe-id ВАШ_UNIVERSE_ID --place-id ВАШ_PLACE_ID --run-id save-01-try-1
```

Появятся `build/cloud-test.project.json` и `build/cloud-test.rbxlx`. Исходники и
основной проект не меняются. Скрипт ничего не публикует и не обращается к Roblox.
`--check` проверяет параметры без сборки. Числа 123/456 используются только
в локальных тестах генератора и не являются настроенной облачной целью.

QA-проект использует loopback-порт 34873. Все `$path` абсолютные, поэтому проект
корректно собирается и из каталога build. Для синхронизации:

```bash
export PATH="$PWD/.tools/bin:$HOME/.rokit/bin:$PATH"
rojo serve build/cloud-test.project.json --address 127.0.0.1 --port 34873
```

Открыть в Studio именно опубликованный тестовый Place и подключить Rojo к
34873. Это сохраняет реальные GameId/PlaceId открытого Place. Локально открытый
`.rbxlx` с нулевыми IDs намеренно блокируется для облачного режима. Подключение
обычного проекта на 34872 возвращает обычные настройки MemoryPreview.

## Изоляция

- Для Studio QA должны совпасть разрешённые Universe ID и Place ID. При нулевых,
  неизвестных или несовпадающих IDs адаптер не обращается к DataStore и не даёт
  редактируемый дефолт.
- Namespace Studio QA: `NeighborhoodFixer_P0_StudioQA_v1`.
- `--run-id` задаёт область `qa-<run-id>` в этом хранилище. Используйте новый ID
  для следующего прогона и один ID для всех трёх сессий текущего. Подходят от 1
  до 20 строчных латинских букв, цифр и дефисов с буквы или цифры. Вызов без
  `--run-id` сохраняет доступ к старой области `global`.
- В настоящем сервере `IsStudio=false` всегда используется прежний namespace
  `NeighborhoodFixer_P0_v1`, независимо от настроек разработки. Миграции namespace нет.
- При ошибке облачной записи перехода в память нет.
- Studio QA и настоящий Roblox-клиент используют разные namespace. Их прогресс
  нельзя сравнивать как одну запись. Для проверки Roblox-клиента отдельно пройти
  тот же цикл внутри тестовой experience.

Roblox использует общие DataStore для мест одной experience. Поэтому требуется
**отдельная тестовая experience**, а не дополнительный Place внутри боевой.
Studio API Services включать только там. Основание: [официальная документация
DataStore и доступа Studio](https://create.roblox.com/docs/cloud-services/data-stores).
Публикация и изменение доступа к API требуют отдельного поручения пользователя.

## Сверка двух перезаходов в Studio

1. В одиночном Play примите учебный заказ. Покрасьте и проверьте стену.
   Дождитесь возможности сдачи, оставьте заказ активным. В командной строке
   Studio со стороны **Server** выполните первую команду ниже. Скопируйте строку
   с префиксом `SAVE01` из Output.
2. Остановите Play, снова запустите его в том же Place и проверьте в игре
   восстановление покраски. До редактирования покрытия или сдачи выполните
   вторую команду и скопируйте строку.
3. Сдайте эту же стену, купите одно растение за $180, разместите его и
   дождитесь подтверждения и финального шага обучения. Выполните третью команду.
4. Снова остановите и запустите Play. Проверьте растение в комнате и выполните
   четвёртую команду до любых новых действий.

```lua
print(require(game.ServerStorage.CloudQASnapshot)("wall-before"))
print(require(game.ServerStorage.CloudQASnapshot)("wall-after"))
print(require(game.ServerStorage.CloudQASnapshot)("furniture-before"))
print(require(game.ServerStorage.CloudQASnapshot)("furniture-after"))
```

Команды выполняются по одной на соответствующем шаге. Модуль включается только
в сборку с `--run-id`. Он читает запись через `GetAsync` с выключенным кешем и
сопоставляет её с состоянием игрока. Соберите четыре строки Output в один
текстовый файл по порядку и запустите скрипт сверки.

```bash
python3 scripts/verify_cloud_test.py путь/к/save-01-output.txt
```

Сверка требует три последовательных захвата свежего профиля. Она сравнивает
маску стены и ревизию до и после первого перезахода, а после второго проверяет
квитанцию сдачи, $70, 50 XP, завершение обучения, экземпляр растения и его позу.
Если команду в рамках одного шага выполнили повторно, оставьте в файле один
снимок этого шага. После лишнего запуска Play начните новый прогон с другим
`--run-id`.

## Проверка на настоящем backend

1. Проверить положительные UserId/GameId/PlaceId, совпадение QA-настроек и
   `Storage.preview=false`, `Storage.blocked=nil`. В Home должен быть облачный
   режим; ошибка загрузки не должна давать нового персонажа с редактируемым $0.
2. Покрасить и проверить стену. Дождаться подтверждения проверки, остановить
   Play до сдачи и запустить снова. Вернуться к заказчику и проверить, что
   покрытие восстановилось, сдача доступна, а баланс прежний. Для заказа
   на две стены отдельно повторить вход после проверки первой стены.
3. Сдать заказ, купить растение и установить его. Записать баланс, instanceId,
   housing revision и локальную позу в приватный QA-отчёт.
4. Остановить Play. В Output найти `profile_release` с `outcome:"ok"` и
   тем же `trace`, что у `profile_load`. Запустить снова в том же тестовом
   Place. Баланс, экземпляр предмета, расстановка и обучение должны
   восстановиться с новым `trace` для загрузки.
5. Повторить запрос покупки и сдачи: дополнительного списания/награды нет.
6. Переместить предмет, убрать на склад, снова установить и повторить вход.
7. Проверить отказ при отключённом API и конфликте двух сессий: нет дефолтного
   редактируемого профиля, чужая или просроченная сессия не пишет.
8. Для настоящего Roblox-клиента отдельно проверить выход/перезаход в приватной
   тестовой experience. Studio-run не выдавать за эту проверку.

Не редактировать и не очищать production-записи ради тестов. Ключ, metadata,
lease/fence и протокол повторов описаны в [PROFILE_STORAGE.md](PROFILE_STORAGE.md).
Пока эти сценарии реально не выполнены, SAVE-01 не закрывается.

Локальная автоматическая проверка прогоняет настоящий Storage и ProfileStore
с имитацией UpdateAsync. На первом входе проверяется 84/96 клеток, после
перезахода сохраняются маска и $0. Потерянный ответ при сдаче даёт одну выплату
$250. После покупки и установки растения «Коралл» следующий вход восстанавливает
$70, 50 XP, завершённое обучение, тот же экземпляр и его локальную позу.

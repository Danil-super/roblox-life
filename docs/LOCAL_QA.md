# Повторяемая локальная приёмка P0

`scripts/studio_local_qa.py` проходит учебный цикл настоящим вводом через
официальный Studio MCP. Он работает с одной уже открытой сценой и сам не
запускает/не закрывает Studio, не создаёт игроков, не редактирует Source,
не выдаёт деньги/XP и не вызывает игровые remotes напрямую.

Это дополнительная автоматизация при доступном официальном MCP. Базовая
разработка через Rojo, `dev.sh check` и ручные сценарии `tests/README.md`
продолжают работать без подключения MCP.

Нужен свежий одиночный Play с каноническими исходниками: Ready, MemoryPreview,
$0, 0 XP, INTRO, вне редактора. Обычный `StudioDataStoreTest` должен быть
выключен. Прогон отказывается от другого проекта, нескольких Studio, облачного
QA и уже начатого профиля. Текущий сеанс с мебелью он не сбрасывает.

ID берётся из официального `list_roblox_studios`; это UUID окна, а не PID.
Подставь актуальный ID в `QA_STUDIO_ID`:

```bash
QA_STUDIO_ID='ID_ИЗ_list_roblox_studios'
python3 scripts/studio_test.py start --studio-id "$QA_STUDIO_ID"
python3 scripts/studio_local_qa.py --studio-id "$QA_STUDIO_ID"
```

Пока прогон работает, не управляй персонажем. Проверяются:

1. Принятие учебного заказа, ходьба по маршруту, разговор, осмотр, подготовка
   и выбор цвета через видимые кнопки.
2. Восемь рядов настоящих движений мыши, серверный порог покрытия, Review
   и сдача клиенту; реальные $250/50 XP.
3. Пеший путь в магазин, покупка растения за $180 в iPhone 7 emulator.
4. Возврат домой, установка `(8,6,0°)`, DONE, одна реальная модель и закрытый
   редактор без ghost. Факт Mouse/Touch проверяется через InputBegan.
5. Перенос `(9,6,0°)`, склад и повторная установка `(8,6,0°)` на ПК без
   дополнительного списания; переход «Назад → Jobs» без лишнего редактора.
6. Принятие Mint, повторное открытие Jobs и подтверждённая отмена; $70/50 XP.
7. Настоящий Output: ожидаемые события, уникальные ревизии, нет повторной
   выплаты/покупки, суммы соответствуют игровым наблюдениям.

Результат последней попытки: `.tools/local-qa/latest.json`. Он содержит дату,
пройденные этапы, статус, итоговые счётчики и границы проверки. В отчёт не
пишутся UserId, имена, ID предметов/операций, raw Output или профили. При ошибке
записывается `failed`; старый `passed` не остаётся результатом новой попытки,
даже если подключение к MCP не удалось. Ошибка cleanup тоже снимает успех.

После прогона Play остаётся доступен для осмотра. Подписки наблюдения снимаются,
устройство возвращается к `default` в Play. Для Stop:

```bash
python3 scripts/studio_test.py stop --studio-id "$QA_STUDIO_ID"
```

Остановка обычного MemoryPreview сбрасывает прогресс этого локального сервера.
Для повторения нужен новый Play. При ошибке прогон останавливается и оставляет
игровое состояние для разбора; продолжать кликать скрытые элементы нельзя.

## Проверенный ввод GUI

`scripts/studio_ui.py` проверяет путь внутри NeighborhoodHUD, видимость всех
родителей/ScreenGui, размер, clip и список GUI под центром кнопки. Кнопка
должна быть Active/Interactable и не перекрываться другой веткой интерфейса.
После клика можно требовать видимость ожидаемой панели. Недоставленный
переход не повторяется автоматически: повтор мог бы переключить меню обратно
или продублировать действие.

```bash
python3 scripts/studio_ui.py InventoryPanel.Back \
  --studio-id "$QA_STUDIO_ID" --expect HomePanel
```

Для Python-сценариев используется `studio_ui.click(client, studio_id, path,
expect="Panel")`. Утилита читает состояние через `execute_luau`, затем
использует официальный `user_mouse_input`. Прямые координаты остаются только
для игровых жестов по стене/полу при проверенном рабочем режиме.

Проверка консервативна: перекрытие декоративным GUI тоже может остановить
тест. Между проверкой и вводом остаётся временной промежуток, поэтому
после переходов нужны наблюдения результата. Это не гарантия атомарного ввода.

## BUILD-UI-QA-08: установленная причина

В solo Play записана последовательность Activated/InputBegan/Building.
Первая установка, перенос, склад и повторная установка завершались с
`Building=false`, без ghost, с подтверждённой позой и $70. Затем старый
сценарий обращался к `HomePanel.Apps.Jobs`, хотя `HomePanel.Visible=false`.
Под центром скрытой кнопки находилась видимая Inventory/Place. Настоящее
Activated получила Place, после чего редактор закономерно открылся снова.

Таким образом, воспроизведённый лишний вход вызван маршрутом автоматического
теста. Защитная проверка отклонила скрытую Jobs до отправки ввода: ревизия,
деньги и число событий остались прежними. «Inventory → Назад → Jobs» прошёл
без нового редактора. Маскировать это задержкой в игровых callbacks не нужно.

`StudioUI.test.py` исполняет настоящий Lua preflight с детерминированной
границей GUI и проверяет отсутствие ввода при отказе. `StudioLocalQA.test.py`
проверяет отказы по профилю/проекту, разбор и согласованность счётчиков Output,
ошибки подключения и обновление отчёта. Оба входят в `dev.sh check`.

Это локальная часть QA-01: эмулированный Touch и один игрок. Облачный rejoin,
физический телефон, многоклиентская изоляция в Roblox и показатели удержания
этим прогоном не подтверждаются.

## Фактический результат 2026-11-05

Полный CLI-прогон со свежего профиля завершился с кодом 0 и `status=passed`:
все восемь рядов покраски, $250/50 XP, Touch-покупка/установка, DONE, перенос,
склад/повторная установка, принятие/отмена Mint. Остались одна модель, $70
и 50 XP. Output подтвердил девять уникальных ревизий и ожидаемые события;
cleanup снял QA-подписки и восстановил default. Отдельное чтение после
завершения подтвердило отсутствие observer, ghost и активного редактора.

Предыдущие попытки честно завершились `failed`: обнаружены обращения к
скрытым Objective/Jobs после автоматического перехода в Paint. Лишний клик
после выбора цвета удалён: игра уже сама включает покраску. Для первой
установки учтён авто-показ Guide и последующее явное открытие склада.
Отказ на уже начатом профиле также проверен в настоящем Play без ввода.
Это исправления сценария, игровые операции и данные не подменялись.

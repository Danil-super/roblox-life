Его SHA-256: `1a5aa35e74907cba8f366edffab2c45444c255cb3dba3cd25dad0a824d7f6e4d`.
Системный Wine не переустанавливался.

Папка проекта выдана sandbox на чтение. Сеть в разрешениях Vinegar уже включена.

Studio действительно создала графические окна; проверено изображение её диалога.

### Чёрный квадрат поверх редактора

На этой машине воспроизведён [сбой Vinegar #973](https://github.com/vinegarhq/vinegar/issues/973):
одно из шести отдельных служебных окон с точным заголовком `RobloxStudio`
и размером 100×100 показывалось поверх редактора. Его содержимое — чёрный фон;
это не деталь квартиры и не игровой GUI. Первоначально найденное окно скрыто
через X11 без уничтожения процесса Studio.

Первоначально включён рекомендованный в issue обход Virtual Desktops
(`1814x1024`), пользователь подтвердил исчезновение квадрата. На следующем
этапе выяснилось, что внутренний размер Studio остаётся около 800×600,
хотя внешняя рамка растёт. В этой установленной сборке Kombucha запросы
EnumDisplaySettings/ChangeDisplaySettings не позволили согласовать размеры.
Экспериментальный Windows helper в проект не включён; Go для работы проекта
не требуется, временный SDK и бинарник эксперимента удалены.

3 ноября 2026 выбран обычный режим Studio (`virtual_desktop = ""`). Перед
изменением пользовательский config.toml сохранён рядом как
`config.toml.before-dynamic-native-*`. Studio на стартовом экране закрыта
штатным WM_DELETE_WINDOW, затем Vinegar перезапущен. Настройки DPI не менялись.

`scripts/desktop_window.py` и включённая пользовательская служба
`roblox-life-desktop.service` через GNOME/XWayland:

- скрывают только окна точного класса RobloxStudioBeta с заголовком
  `RobloxStudio` и размером 100×100; остальные вспомогательные окна остаются;
- подгоняют основное обычное окно Studio при запуске и изменении монитора,
  рабочей области или рамки; учитывают панель, декорации и запас 8 px;
- не подгоняют диалоги/дочерние окна и сохраняют ручной размер до изменения
  конфигурации мониторов; разрешение и DPI системы не изменяют.

На настоящем окне проверены 1280×800 и 1700×900: содержимое стартовой страницы
перестраивается, затем квартира/персонаж/HUD отображаются и в Play. Нативное
служебное окно 100×100 после перезапуска имеет `IsUnMapped`; квадрат отсутствует.
13 Python-тестов проверяют выбор монитора, геометрию для уменьшающихся и
растущих разрешений, отрицательные координаты и точный фильтр служебного окна.
После этого выполнено настоящее временное переключение через официальный
D-Bus интерфейс Mutter: 1920×1080 → 1280×720 → 1920×1080. Служба сама изменила
клиентскую область Studio 1904×995 → 1264×635 → 1904×995. Исходный режим
восстановлен в finally; масштаб 1.0 не менялся, постоянная конфигурация монитора
не записывалась. Подключение второго дисплея отдельно не проверялось; поддержка
чистого Wayland без XWayland не заявляется. Описание метода получено из
[официального интерфейса Mutter](https://github.com/GNOME/mutter/blob/main/data/dbus-interfaces/org.gnome.Mutter.DisplayConfig.xml):
в Context7 сведений об этом D-Bus методе не оказалось.

Установка, разовая подгонка и отключение службы описаны в README. При переносе
репозитория службу нужно переустановить из нового пути. Обход локальный;
будущая версия Vinegar/Studio может потребовать повторной проверки.

## Ограничения прототипа

- Монеты сохраняются только в памяти сессии. Сохранений, покупок, мебели и
  платёжных интеграций нет.
- Условия действия проверяются в начале и конце. Отдельного контроля
  телепортации или непрерывного отслеживания перемещения нет.
- Стандартного персонажа создаёт Roblox при Play, отдельной модели персонажа
  в `.rbxlx` нет. Его появление в реальном Play подтверждено.
- Работа Studio через Wine зависит от версии Studio, Vinegar и драйвера GPU.
  Успешный Linux build не гарантирует работоспособность Windows Studio.

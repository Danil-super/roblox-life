# HUD в низком окне

Main.resize больше не пропускает поддерживаемые окна ниже 240 safe px.
Проверяемый минимум desktop-раскладки — 280×224, после Roblox CoreUISafeInsets.
Произвольно малые viewport не поддерживаются; предел отмечен в коде.
Проверенные touch-размеры остаются прежними, это не приёмка любого узкого
ландшафтного формата на физическом телефоне.

На ПК при Ready и высоте <360 кошелёк, телефон и язык занимают верхний ряд
по 44 px. Прежняя маршрутная карточка 242×64 находится ниже; цель и действие
остаются в карточке 100 px у нижней границы. Геометрия HudLayout проверяет
отсутствие пересечений. Заголовок кошелька и суффикс клавиши M скрыты;
сама клавиша и телефон используют прежний обработчик. При увеличении окна
детали и суффикс возвращаются. Серверный статус профиля не меняется.

В компактной карточке 100 px JobHintError показывает текст ошибки вместо
заголовка цели; действие остаётся на месте. Истечение ошибки возвращает
цель, полная раскладка возвращает прежние позиции текста. Renderer не
переписывает подтверждённый текст ошибки. Минимальная touch-карточка 60 px
не получает наложенный поверх действия текст.

При высоте <252 из телефона убирается подпись приватности; список приложений
начинается выше и вмещает полную строку кнопок ≥44 px. Остальное содержимое
прокручивается. Приватность комнаты и доступ проверяет прежний сервер.
CanvasPosition/выбранный заказ/ожидающие операции resize не сбрасывает.

Нет новых объектов, кадровых циклов, подписок, зависимостей и remotes.
Обычный desktop и существующие touch-макеты сохраняют размеры. Компактная
ошибка дополнительно видна в прежних карточках 100 px. Profile_Load_Error
сохраняет приоритет; resize не разблокирует игровые действия.

HudLayout.test.luau проверяет bounds/пересечения пяти низких размеров,
quiet, 359/360 и приоритет ошибки профиля. HudResizeUI.test.py исполняет
настоящие Main.resize/phoneCaption: большой → низкий → граничный → большой,
EN/RU, ошибка/истечение, список приложений, Touch и профиль. Оба входят
в `bash scripts/dev.sh check`; старый Main воспроизводит stale Home.

Нативную приёмку выполнять в одном solo MemoryPreview: уменьшать именно
окно Studio, а не подменять AbsoluteSize. Проверять фактические размеры,
TextFits/границы/перекрытие и реальные Home → Jobs → Back → Close для EN/RU.
В Wine/Wayland размер может округляться на пиксель; допуск ширины теста
не отменяет strict preflight или проверку измеренной геометрии.

10 ноября выполнены 14 native EN/RU-проверок: 1449×846 → 625×230 →
569×224 → 625×358 → 625×360 → 625×230 → 1449×846. На каждом шаге
Home → Jobs → Back → Close прошёл preflight; геометрия/TextFits/цели ≥44 px
и $0/0 XP проверены. Два снимка подтвердили внешний вид низкого HUD/телефона.
Прежний игровой цикл затем дал девять подтверждённых пакетов, $70/50 XP
и один предмет. Прогон остановился в Edit и вернул размер окна.

11 ноября после перерыва подтверждён сохранённый отчёт и совпадение 85 Source
сборки с диском. Studio уже закрыта; свежая runtime-сверка не выполнялась.
Приоритет ошибок/профиля и quiet проверен локальными callbacks, не отдельным
нативным сбоем. Физический телефон, cloud/rejoin и несколько клиентов отдельно.
Факты и ограничения: [ENVIRONMENT.md](ENVIRONMENT.md).

API сверены через Context7 с официальными
[ScreenGui](https://create.roblox.com/docs/reference/engine/classes/ScreenGui)
и [GuiBase2d](https://create.roblox.com/docs/reference/engine/classes/GuiBase2d).

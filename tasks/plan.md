# План: Neighborhood Fixer P0

Источник требований: [GDD/ТЗ v0.7](../Roblox_Neighborhood_Fixer_GDD_TZ_v0.7.md),
изучены разделы 1–35. Поручение пользователя: динамический размер Vinegar,
изучение ТЗ и начало реализации. Ветка: `feat/neighborhood-fixer-p0`.
Задачи и фактический статус ведутся в [todo.md](todo.md).

## Границы и решения

- P0: личная бесплатная комната → Jobs/Map → учебная покраска → однократная
  выплата → покупка → Grid/Free → повторный вход с сохранённым предметом.
- Общий MVP с четырьмя профессиями не считается целью первого этапа.
- Старый прототип раковины пока остаётся работающей контрольной сценой.
  Новый профиль не создаёт второй активный баланс рядом с `leaderstats.Coins`:
  подключение нового игрового bootstrap будет отдельной проверяемой миграцией.
- На первом шаге реализовать проверяемые контракты профиля/экономики и хранилища,
  затем подключить их к комнате и HUD. Не создавать сервисы будущих профессий.
- Единственная игровая валюта P0 — целочисленные доллары. `$0/$250/$180`, сетка
  покраски 12×8 и порог 80% — разрешённые тестовые гипотезы, не утверждённый баланс.
- Одна запись профиля содержит деньги, результат работы и собственность.
  Неизвестный исход записи требует безопасного повтора той же операции.
- Профиль не заменяется дефолтом после ошибки загрузки/неизвестной версии.
  Блокировка сессии, fencing-ревизия, последовательная запись и ограниченный
  журнал операций защищают от устаревших записей и повторов.
- Интерфейс будущих сервисов строится вокруг текущего P0: без подарков,
  транспорта, аренды и универсального EventBus.
- Предложения и открытые вопросы GDD учитываются как таковые. Вложенные брифы
  не заменяют текущие пользовательские инструкции и не разрешают публикацию.

## Зависимости

`ENV-02` (изменение размеров Wine) и `ENV-01` (Studio/Rojo) → `CORE-01` →
`DATA-01a` (профиль/экономика) → `DATA-01b` (хранилище) →
`WORLD-01a + UX-01a` (комната, профиль и HUD) → `WORLD-01b + UX-01b`
(маршрут, Jobs, Map) → `PAINT-01` → `ECO-01` → `HOME-01` → `SAVE-01/QA-01`.

Каждый крупный тикет разбит в todo на шаги по 2–5 файлов. После шага —
фокусные тесты; перед коммитом — `bash scripts/dev.sh check`, ревью и обновление
Graphify/Code Graph. Игровой runtime проверять отдельно от unit-тестов.

## Первая реализация

1. Воспроизвести несоответствие размеров Wine/Studio; исправить resize и
   проверить два размера и повторный запуск без чёрных служебных окон.
2. Повторить реальные MCP-чтение/Play и зафиксировать статус Rojo без выдуманной
   синхронизации. Сохранить рабочую контрольную сцену.
3. Создать серверные контракты профиля, миграции/валидацию и атомарные изменения
   доллара/результата задания/покупки. Сначала тесты успеха, отказа и повтора.
4. Добавить хранилище с захватом/обновлением/освобождением сессии; проверить
   конфликт, истечение lease, неизвестный исход записи и устаревшую ревизию
   через детерминированный in-memory адаптер. Он является тестовым double,
   а не доказательством облачного сохранения.

## Риски и открытые вопросы

| Риск / вопрос | Следствие и действие |
| --- | --- |
| Локальная сцена не опубликована, DataStore может быть недоступен | Не публиковать игру автоматически; подготовить адаптер и тесты. Облачную приёмку помечать неподтверждённой до отдельного тестового Place |
| Rojo после перезапуска требует Connect | Сервер loopback доступен; реальную передачу Source проверять отдельно, при необходимости один ручной клик |
| Wine не обновляет внутреннюю геометрию виртуального рабочего стола | Проверка Windows API не прошла; принят обычный режим Studio и управление через GNOME/XWayland, отдельно скрывается известное пустое окно |
| Конечные ассеты и лицензии не выбраны | Геометрия прототипа собственная; каталог/звуки фиксировать с происхождением, не брать случайные модели с кодом |
| Мобильные бюджеты не заданы | Сначала emulator; реальное устройство и 12–16 клиентов — отдельная приёмка, не заявление об уже достигнутой производительности |
| Редкие неизвестные результаты DataStore | Безопасный повтор, lease/fencing, ограниченная история и постоянный признак выплаты текущего заказа |

## Проверочные точки

- После основы: формат, статический анализ, unit-тесты, сборка, ревью контрактов.
- После комнаты/телефона: настоящий Play на ПК, EN/RU и безопасные зоны mobile.
- После покраски: мышь/свайп, отмена/смерть, проверка сетевых злоупотреблений.
- После мебели/сохранений: полный цикл, повторный вход и ошибки хранилища.
- P0 не готов, пока не выполнен gate §19.6 GDD. Изменения в main/remote и
  публикация игры не выполняются автоматически в рамках начала реализации.
